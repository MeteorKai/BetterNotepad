2026.9.19
-修复选中多行文本时选区高亮行与行之间不对齐的问题：中间各行的选区背景比首末行向左、向右各多出
  约 12px，看起来「一行一个位置」，而文字本身是对齐的
-原因：CodeMirror 的选区层用「.cm-content 的矩形 + .cm-line 的左右内边距」计算选区边界，
  看不到 .cm-content 自身的水平内边距，因此内容容器的 12px 水平内边距会让整段选区的边界算错。
  现把水平内边距移到 .cm-line 上（12px + 基础主题自带的 6px / 2px），文字位置与自动换行宽度完全不变
-移除「应用内自动更新」：设置 › About 的「检查更新」按钮改为直接在浏览器打开项目的 GitHub 页面，
  可查看每个版本的安装包与更新说明；启动时不再做后台静默检查，也不再出现更新提示小圆点
-随之不再需要签名密钥、`.sig` 签名与 `latest.json` 更新清单，发版流程简化为「改版本号 → 打包 → 上传 exe」
-版本号提升至 0.3.1

2026.9.22
-新增：输出面板高度可自行拖拽调整。鼠标移到面板顶部边缘会变成上下箭头，按住即可拖动，
  范围 60~640px，调整后的高度会被记住，下次打开仍是这个高度
-新增：输出面板支持键盘输入，可运行需要交互的程序（如 Python 的 input()、C 的 scanf）。
  面板底部新增输入行，输入内容后按回车即可发送给正在运行的程序
-输入行支持历史记录：按 ↑ / ↓ 可翻阅之前输入过的内容，历史跨多次运行保留，最多记住 100 条
-你发送的每一行都会以灰色的「> 内容」形式回显在输出里，方便对照程序输出
-程序未运行时输入行自动禁用并给出提示，避免内容发出去却没人接收
-修复：此前运行的程序完全没有接入标准输入，一旦执行到读取输入的语句就会立刻报错退出
-新增：括号匹配高亮。光标停在 {}、[]、() 旁边时，这一对括号会一起被标记出来，
  嵌套结构里也能正确配对到最近的那个，写代码时一眼就能看清层级
-括号找不到配对时（例如多打了一个右括号）用红色标出，提示这里可能有问题
-设置 › 编辑器 里新增「高亮匹配的括号」开关，可随时关闭
-新增：终端输出。运行脚本时，输出面板现在是真正的终端，和 VSCode 里的终端一样：
  print 一行就立刻显示一行，不再等程序跑完才一起涌出来
-彩色输出正常显示（红、绿、黄、蓝等），不再是一堆乱码转义字符
-进度条（如 tqdm）会原地刷新，不再每刷新一次就往下刷一行
-程序需要键盘输入时可以直接在输出面板里敲，方向键、退格键、Ctrl+C 都能正常工作
-终端模式下底部那行输入栏已去掉（终端本身就能直接输入，不再需要它在下面中转）；
  切回纯文本输出时它仍会出现，因为那种模式下程序只能靠它读取输入
-输出面板右上角新增「终端：开 / 关」按钮，可随时切回原来的纯文本输出；
  设置 › 编辑器 里也有「终端输出」开关
-修复：此前程序输出被缓冲，导致日志和 print 混在一起、顺序错乱，且必须等程序结束才显示
-新增：在 {}、[]、() 这一对括号中间按回车时，会自动展开成三行——光标停在中间那行并缩进一级，
  右括号被移到单独的一行、与左括号所在行的缩进对齐，不用再自己把右括号敲下去；
  括号不配对时保持原来的换行行为
-终端里的输出现在可以像在 VSCode 的终端里一样用鼠标直接选中，选中后按 Ctrl+C 即复制到剪贴板
-没有选中内容时，Ctrl+C 仍然是中断信号，会照常停止正在运行的程序
-移除输出面板右上角的「复制」按钮：终端模式下选中即复制，纯文本模式下仍可通过右键菜单复制
-修复：终端模式下运行 PHP 等程序时，中文报错信息会显示成乱码（例如「找不到指定的模块。」显示为
  「鎵句笉鍒版寚瀹氱殑妯″潡銆?」）。原因是终端控制台默认沿用系统的 OEM 代码页（简体中文 Windows 为 936），
  而这些程序按 UTF-8 写出的报错信息被当成 GBK 重新解释；现在每次运行前会先把控制台切到 UTF-8，
  报错信息恢复可读，中文输入也能正确传给程序
-修复：窗口没有最大化时打开看板娘会完全看不见。此前记录的是屏幕上的绝对坐标，在最大化时存下的位置
  换到还原后的小窗口里就落到窗口外面了，而且拖不回来（只能重新最大化才看得见）。现在改为记录「距窗口
  右下角的距离」，并在每次打开时把位置夹进窗口范围内，窗口多大都能正常显示与拖动
-版本号提升至 0.4.1
